===== Cybersecurity Standards =====
-- Security Architecture
  * Zero Trust Architecture Model [Build|ISO Security Architect] :: All network access must assume breach; verify explicitly, use least privilege, assume breach
  * Defense in Depth Strategy [Build|ISO Security Architect] :: Implement multiple layers of security controls across network, application, data, and endpoint
  * Threat Modeling (STRIDE) [Build|ISO Security Architect] :: All new systems must complete STRIDE threat modeling before design approval
  * Security Reference Architecture [Build|ISO Security Architect] :: Standard patterns for cloud (VPC, subnets, security groups), on-prem, and hybrid deployments
  * Data Flow & Trust Boundaries [Build|ISO Security Architect] :: All data flows must be documented with trust boundary classifications
-- Encryption
  * Encryption at Rest Standard [Build/Run|ISO Security Architect] :: AES-256 for all data at rest; database TDE enabled for sensitive data stores
  * Encryption in Transit Standard [Build/Run|ISO Security Architect] :: TLS 1.2+ required for all external communications; TLS 1.3 preferred
  * Key Management Standard [Build/Run|ISO Security Architect] :: All keys managed via approved KMS/HSM; no hardcoded secrets; rotation policy enforced
  * Certificate Management [Run|ISO Security Architect] :: PKI certificates must use 2048-bit RSA or higher; annual rotation required
-- Identity & Access
  * Role-Based Access Control (RBAC) [Build/Run|Identity Access Manager] :: All access must be role-based with documented role definitions and periodic access reviews
  * Privileged Access Management (PAM) [Run|Identity Access Manager] :: All privileged access via PAM tool; just-in-time access; session recording for admin activities
  * Multi-Factor Authentication (MFA) [Run|Identity Access Manager] :: MFA required for all external access, privileged accounts, and sensitive systems
  * Service Account Management [Build/Run|Identity Access Manager] :: All service accounts documented, non-interactive, least privilege, password rotation automated
  * Break-Glass Procedures [Run|Identity Access Manager] :: Documented emergency access procedures with dual approval and mandatory audit trail
  * Access Request & Provisioning SLA [Run|Identity Access Manager] :: Access requests processed within 4 business hours; provisioning within 24 hours
-- Application Security
  * Secure SDLC Requirements [Build|Application Security Lead] :: Security gates at design, code, test, and deploy phases; security champion in each squad
  * SAST (Static Analysis) [Build|Application Security Lead] :: All code must pass SAST scan before merge; critical/high findings block deployment
  * DAST (Dynamic Analysis) [Build|Application Security Lead] :: DAST scans required pre-production; OWASP Top 10 coverage mandatory
  * SCA (Dependency Scanning) [Build|Application Security Lead] :: Third-party libraries scanned for vulnerabilities; no critical CVEs in production
  * Container Security [Build|Application Security Lead] :: Base images from approved registry only; image scanning mandatory; no root containers
  * API Security Standards [Build|Application Security Lead] :: OAuth 2.0/OIDC for API auth; rate limiting; input validation; no sensitive data in URLs
  * Secrets Management [Build|Application Security Lead] :: No secrets in code; use approved vault (HashiCorp, Azure Key Vault, AWS Secrets Manager)
-- Vulnerability Management
  * Vulnerability Scanning Cadence [Run|Cybersecurity Lead] :: Weekly vulnerability scans for all production systems; monthly for non-prod
  * Patch Management SLA [Run|Cybersecurity Lead] :: Critical: 72 hours, High: 7 days, Medium: 30 days, Low: 90 days
  * Penetration Testing [Run|Cybersecurity Lead] :: Annual third-party pen test; quarterly internal pen test for critical systems
  * Remediation Tracking [Run|Cybersecurity Lead] :: All critical/high vulnerabilities tracked to closure; exceptions require CISO approval
-- Security Operations
  * SIEM Integration [Run|SOC Lead] :: All applications must log to enterprise SIEM (Sentinel/Splunk); log shipping within 5 min
  * Security Event Logging [Build/Run|SOC Lead] :: Authentication, authorization, data access, configuration changes must be logged
  * Alert Thresholds & Tuning [Run|SOC Lead] :: Alert thresholds documented and tuned quarterly; false positive rate <10%
  * Security Playbooks [Run|SOC Lead] :: Documented playbooks for top 20 security alerts; tested quarterly
  * Log Retention [Run|SOC Lead] :: Security logs retained per policy: 90 days hot, 1 year warm, 7 years archive (compliance)
-- Incident Response
  * IR Plan & Escalation [Run|SOC Lead] :: Documented IR plan with severity definitions; escalation within 15 min for Sev1
  * Severity Definitions [Run|SOC Lead] :: Sev1: Active breach/data loss, Sev2: Attempted breach, Sev3: Vulnerability, Sev4: Anomaly
  * Forensics Readiness [Run|SOC Lead] :: Forensic tools and procedures documented; evidence preservation within 1 hour
  * Tabletop Exercises [Run|SOC Lead] :: Quarterly tabletop exercises; annual full IR simulation
-- Data Protection
  * Data Classification [Build/Run|ISO Security Architect] :: All data classified: Public, Internal, Confidential, Restricted; labeling enforced
  * PII/PHI Handling [Build/Run|ISO Security Architect] :: PII/PHI fields identified and documented; encryption, masking, or tokenization required
  * Data Masking/Tokenization [Build|ISO Security Architect] :: Production data masked in non-prod environments; tokenization for payment data
  * Data Retention & Minimization [Run|ISO Security Architect] :: Retention policies enforced; data minimization principle applied; no unnecessary PII
  * Secure Data Transfer [Run|ISO Security Architect] :: SFTP, encrypted email, or approved secure file transfer for sensitive data
-- Compliance
  * Security Controls Matrix [Run|ISO Security Architect] :: NIST CSF or ISO 27001 controls mapped to systems; annual control attestation
  * Risk Register [Run|ISO Security Architect] :: All security risks documented in enterprise risk register; quarterly review
  * Vendor Security Assessment [Build/Run|ISO Security Architect] :: Third-party vendors assessed before engagement; annual reassessment for critical vendors
  * Security Exception Process [Run|ISO Security Architect] :: All exceptions require risk acceptance, compensating controls, and CISO approval
-- Infrastructure
  * OS Hardening Guidelines [Build|ISO Security Architect] :: CIS benchmarks applied; unnecessary services disabled; secure configuration baseline
  * Database Hardening [Build|ISO Security Architect] :: Database TDE enabled; network access restricted; audit logging enabled
  * Network Segmentation [Build|ISO Security Architect] :: Firewall rules documented; microsegmentation for sensitive workloads; DMZ required
  * Cloud Security Posture [Run|ISO Security Architect] :: CSPM enabled; misconfigurations auto-detected; IAM policies reviewed quarterly
===== Architecture Standards =====
-- Architecture Principles
  * Business-Aligned Technology [Build|Enterprise Architect] :: All technology decisions must demonstrably support business capabilities and outcomes
  * Reuse Before Buy Before Build [Build|Enterprise Architect] :: Leverage existing capabilities first; evaluate commercial solutions; custom build as last resort
  * Loose Coupling [Build|Solution Architect] :: Systems should minimize dependencies; use event-driven patterns; design for replaceability
  * Design for Failure [Build|Solution Architect] :: All systems must handle failures gracefully with retry, circuit breaker, and fallback patterns
  * API-First Design [Build|Solution Architect] :: All capabilities exposed via well-defined APIs; internal services are first-class API consumers
  * Data as an Asset [Build|Data Architect] :: Data is owned, governed, and treated as a strategic enterprise asset with clear stewardship
-- Technology Stack
  * Approved Languages [Build|Enterprise Architect] :: Java 17+, Python 3.10+, TypeScript/Node.js 18+, C# .NET 6+; exceptions require ARB approval
  * Approved Databases [Build|Data Architect] :: PostgreSQL, SQL Server for OLTP; Snowflake, Databricks for analytics; Redis for caching; MongoDB for document stores
  * Approved Cloud Platforms [Build|Cloud Architect] :: Azure (primary), AWS (secondary for specific workloads); multi-cloud by exception only
  * Approved Messaging [Build|Solution Architect] :: Azure Service Bus, Kafka for event streaming; RabbitMQ deprecated; no new TIBCO implementations
  * Approved Integration [Build|Solution Architect] :: Azure API Management for API gateway; MuleSoft for legacy integration; GraphQL for BFF patterns
  * Approved Observability [Run|Solution Architect] :: Azure Monitor, Dynatrace for APM; Splunk for logs; PagerDuty for alerting; Grafana for dashboards
  * Container Platforms [Build|Cloud Architect] :: AKS (Kubernetes) for container orchestration; Docker for local development; Helm for packaging
  * CI/CD Tooling [Build|Solution Architect] :: Azure DevOps or GitHub Actions for pipelines; SonarQube for quality gates; Artifactory for artifacts
-- Architecture Patterns
  * Microservices Criteria [Build|Solution Architect] :: Services <500 LOC business logic; single bounded context; independent deployment; team ownership
  * Event-Driven Architecture [Build|Solution Architect] :: Use events for cross-domain communication; eventual consistency acceptable for non-financial data
  * Domain-Driven Design [Build|Solution Architect] :: Strategic DDD for domain modeling; bounded contexts map to teams; ubiquitous language enforced
  * CQRS Pattern [Build|Solution Architect] :: Separate read/write models for high-scale scenarios; event sourcing optional for audit-heavy domains
  * Backend-for-Frontend (BFF) [Build|Solution Architect] :: Dedicated API layer per client type (web, mobile, partner); aggregation at BFF layer
  * Strangler Fig Migration [Build|Solution Architect] :: Legacy modernization via incremental replacement; new traffic to new system; gradual cutover
  * Saga Pattern [Build|Solution Architect] :: Distributed transactions via choreography (events) or orchestration (workflow engine)
  * Sidecar/Service Mesh [Build|Cloud Architect] :: Istio/Linkerd for cross-cutting concerns (mTLS, retries, observability) in Kubernetes
-- API Standards
  * API Design Guidelines [Build|Solution Architect] :: RESTful design; resource-oriented; HATEOAS for discoverability; consistent naming conventions
  * API Versioning [Build|Solution Architect] :: URI versioning (v1, v2) for breaking changes; header versioning for minor; deprecation policy 12 months
  * API Documentation [Build|Solution Architect] :: OpenAPI 3.0 specs required; auto-generated from code; published to developer portal
  * API Security [Build|Solution Architect] :: OAuth 2.0 + OIDC; API keys for partners; rate limiting; input validation; no PII in URLs
  * API Performance [Build|Solution Architect] :: P95 latency <200ms; pagination required for collections; caching headers; compression enabled
  * API Error Handling [Build|Solution Architect] :: RFC 7807 Problem Details format; consistent error codes; no stack traces in production
  * API Contracts [Build|Solution Architect] :: Consumer-driven contracts; contract testing in CI/CD; breaking changes require consumer notification
-- Cloud Architecture
  * Landing Zone Standards [Build|Cloud Architect] :: Standard subscription structure; network topology; identity integration; policy guardrails
  * Network Architecture [Build|Cloud Architect] :: Hub-spoke topology; private endpoints; no public IPs except load balancers; NSG/firewall rules documented
  * Infrastructure as Code [Build|Cloud Architect] :: Terraform (preferred) or Bicep; no manual changes; GitOps workflow; drift detection enabled
  * Resource Naming Convention [Build|Cloud Architect] :: Standard naming: {env}-{region}-{app}-{resource}-{instance}; tags required: Owner, CostCenter, Environment
  * High Availability [Build|Cloud Architect] :: Multi-AZ deployment required for production; RPO/RTO documented; auto-scaling configured
  * Disaster Recovery [Build/Run|Cloud Architect] :: DR strategy documented (Pilot Light, Warm Standby, Active-Active); tested quarterly
  * Cost Management [Run|Cloud Architect] :: Resource tagging for cost allocation; rightsizing reviews monthly; reserved instances for steady-state
-- Data Architecture
  * Data Modeling Standards [Build|Data Architect] :: Conceptual, logical, physical models required; ERD in approved tool; naming conventions enforced
  * Master Data Management [Build|Data Architect] :: Golden records for Customer, Policy, Claim, Product; MDM hub for cross-domain resolution
  * Data Quality Standards [Build/Run|Data Architect] :: Quality rules defined; profiling automated; DQ scores published; remediation SLAs
  * Data Lineage [Build|Data Architect] :: End-to-end lineage captured; automated discovery preferred; lineage published to catalog
  * Data Catalog [Build/Run|Data Architect] :: All datasets registered; business glossary linked; stewardship assigned; searchable metadata
  * ETL/ELT Standards [Build|Data Architect] :: ELT preferred for cloud; idempotent pipelines; schema evolution handled; data contracts enforced
  * Analytics Architecture [Build|Data Architect] :: Medallion architecture (Bronze/Silver/Gold); semantic layer for BI; governed self-service
-- Architecture Governance
  * Architecture Review Board (ARB) [Build|Enterprise Architect] :: All major initiatives require ARB approval; meets weekly; decision log maintained
  * Solution Design Review [Build|Solution Architect] :: Solution architecture document required before development; template standardized
  * Technical Design Review [Build|Solution Architect] :: Detailed design reviewed by peers; security, performance, and operability checklist
  * Architecture Decision Records [Build|Solution Architect] :: ADRs required for significant decisions; stored in repo; status tracked (Proposed, Accepted, Deprecated)
  * Technical Debt Register [Build/Run|Enterprise Architect] :: Tech debt logged, prioritized, and scheduled; 20% capacity reserved for debt reduction
  * Reference Architecture Library [Build|Enterprise Architect] :: Approved patterns documented with examples; deviations require justification and approval
  * Architecture Fitness Functions [Build|Solution Architect] :: Automated tests for architecture compliance; run in CI/CD; failures block deployment
-- Documentation
  * Architecture Diagram Standards [Build|Solution Architect] :: C4 model (Context, Container, Component, Code); draw.io or LucidChart; version controlled
  * Non-Functional Requirements [Build|Solution Architect] :: NFRs documented per project: performance, scalability, availability, security, compliance
  * Sequence Diagrams [Build|Solution Architect] :: Required for complex flows; PlantUML or Mermaid; stored with code
  * Architecture Repository [Build|Enterprise Architect] :: Confluence for documentation; Git for diagrams-as-code; searchable and maintained
  * Runbook Requirements [Build|Solution Architect] :: Operational runbooks required before go-live; stored in wiki; reviewed quarterly
===== Claims Standards =====
-- FNOL
  * Intake SLA [Run|Claims Manager] :: FNOL acknowledged within 4 hours; assigned to adjuster within 24 hours
  * Coverage Verification [Run|Claims Adjuster] :: Coverage confirmed within 24 hours of assignment; denial letters within 72 hours if no coverage
  * Initial Contact [Run|Claims Adjuster] :: Insured contacted within 24 hours of assignment; contact attempts documented
-- Reserving
  * Initial Reserve Standards [Run|Claims Adjuster] :: Initial reserve set within 72 hours based on reserve worksheet; documented rationale required
  * Reserve Adequacy Review [Run|Claims Manager] :: Reserves reviewed at 30/60/90 days; manager approval for changes >$25K
  * Large Loss Threshold [Run|Claims Manager] :: Claims >$100K require senior adjuster assignment; >$500K require manager oversight
-- Investigation
  * Investigation Standards [Run|Claims Adjuster] :: Recorded statements within 14 days; scene inspection within 72 hours for property; subrogation potential identified
  * Documentation Requirements [Run|Claims Adjuster] :: All claim activity documented in system within 24 hours; photos/evidence linked to file
  * Expert Engagement [Run|Claims Adjuster] :: Independent adjusters, engineers, or appraisers engaged per authority matrix
-- Settlement
  * Settlement Authority [Run|Claims Manager] :: Adjuster authority per level; manager approval for policy limits settlements; no nuisance payments
  * Release Documentation [Run|Claims Adjuster] :: Signed release required before payment; subrogation rights preserved where applicable
  * Payment Processing [Run|Claims Adjuster] :: Payments issued within 5 business days of settlement agreement; proper payee verification
-- Quality
  * File Review Standards [Run|Claims Manager] :: 10% of files reviewed monthly; quality scorecard maintained; calibration sessions quarterly
  * Cycle Time Targets [Run|Claims Manager] :: Auto: 30 days avg; Property: 45 days avg; Liability: 90 days avg; Complex: 180 days
  * Customer Satisfaction [Run|Claims Manager] :: Post-claim survey sent; NPS target >40; complaints escalated within 24 hours
-- Fraud/SIU
  * Red Flag Indicators [Run|Claims Adjuster] :: Documented red flag checklist; referral to SIU within 48 hours if triggered
  * SIU Investigation Standards [Run|SIU Manager] :: Investigation plan within 5 days; law enforcement coordination documented; outcome tracked
-- Subrogation
  * Recovery Standards [Run|Claims Manager] :: Subrogation potential evaluated on every claim; recovery tracked to closure; contingency fee approval
-- Litigation
  * Litigation Management [Run|Claims Manager] :: Defense counsel from approved panel; litigation plan required; reserve adjusted for legal exposure
-- Reinsurance
  * Reinsurance Notification [Run|Claims Manager] :: Treaty notification per contract terms; facultative claims reported within 72 hours
